# Изменения на ветке backend/mongo

Серверная часть учебного стенда Cargo Guard. Ветка не слита в `main`. Страница Родиона на `main` по-прежнему открывается сама по себе и хранит демо в браузере. Живая база и правила приёмки есть только здесь.

## Как открыть стенд

Нужны Python 3, Git и MongoDB. Служба MongoDB должна быть запущена, адрес по умолчанию `mongodb://127.0.0.1:27017`. Файл `.env` создавать не нужно: адрес базы, имя базы и папка фото уже заданы в коде. Позже для хостинга их меняют переменными `MONGO_URL`, `MONGO_DB` и `PHOTO_DIR`.

```powershell
git fetch
git checkout backend/mongo
git pull
cd backend
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В браузере открыть http://127.0.0.1:8000/ . Страница и API идут с одного адреса, отдельный файл `frontend/index.html` для этого не нужен. Пока сервер выключен, тот же файл по-прежнему работает на своих демо-данных.

Пароль совпадает с логином.

| Логин | Роль на экране | Что можно |
| --- | --- | --- |
| controller | Контролер, Мамбетов Р. Р. | осмотр, кадр серийного номера |
| accounting | Бухгалтерия, Соколова Е. М. | новый заказ, комиссия, отказ в пункте выдачи |
| admin | Администратор, Черакаев А. А. | настройки, удаление, и любой шаг выше |
| security | Служба безопасности | только журнал |

В Compass выбрать соединение `localhost:27017` и базу `cargoguard`. Рядом лежит `cargoguard_test`: её создают проверки, в неё смотреть не нужно. Список запросов сервера: http://127.0.0.1:8000/docs

Проверки правил, они пишут только в `cargoguard_test`:

```powershell
cd backend
$env:MONGO_DB='cargoguard_test'
.\.venv\Scripts\python -m pytest -q
```

Последний прогон: 5 проверок прошли.

## Что добавлено

Сервер на Python и FastAPI. База MongoDB, четыре коллекции: `users`, `orders`, `logs`, `settings`. При первом запуске пустая база `cargoguard` заполняется учебными заказами и пользователями. Если документы уже есть, повторный запуск их не затирает.

Кадр осмотра лежит файлом в `backend/photos`. В заказе хранится имя файла, поле `photoPath`. Сами кадры в Git не попадают. Пока камера на странице учебная, сервер рисует карточку с QR, массой и временем. Тот же адрес принимает и настоящий файл с камеры.

Пароль в базе хранится как `passwordHash` (PBKDF2-SHA256). В ответ странице хеш не отдаётся.

Индексы: уникальные `users.login`, `users.id`, `orders.id`, `orders.qr`, `logs.id`, плюс `orders.stage` и `logs.boxId`. Границы массы в настройках не лежат. Их считает только сервер: до 3 кг включительно группа `0-3`, до 20 кг включительно группа `3-20`, дальше `20+`. На экране группа только показывается.

Комиссию считает сервер в момент закрытия сделки. Число с экрана он не принимает. Стартовые значения: комиссия 3 процента, тарифы 600, 1100 и 1750 рублей. Номера счетов на экране учебные, перевода денег нет.

## Правила приёмки

Группа `0-3` не уходит в пункт выдачи без файла кадра. Ответ 409, этап заказа не меняется. Это отказ закрыть приёмку, а не спор. Спор возникает, когда кадр есть, а проверка возврата товар не подтверждает.

Повтор того же закрытия второй строки в журнале не пишет. Удалить закрытый заказ может только администратор, и перед удалением в журнал попадает строка. Служба безопасности заказ не удаляет.

Этапы те же, что уже были на странице: `warehouse_send`, `in_pvz`, `warehouse_return`, `deal_closed`, `return_completed`, `dispute_closed`, `cancelled_defect`.

- Осмотр отправки подтверждён: заказ уходит в пункт выдачи. Для `0-3` нужен кадр, чек-лист обязателен.
- Осмотр отправки с браком: заказ отменяется. Кадр для этой ветки не требуется.
- Отказ покупателя принимается только из пункта выдачи и открывает проверку возврата.
- Возврат подтверждён: деньги и товар возвращаются по сценарию экрана.
- Возврат не подтверждён: спор закрыт.
- Комиссия списывается только когда покупатель забрал товар.

## Адреса, которые вызывает страница

- `GET /api/state` открыт, чтобы экран мог загрузиться. Если в ответе есть заказы, страница берёт их с сервера.
- `POST /api/orders` создаёт заказ. Тело то же, что страница уже отправляла, плюс поле `role`.
- `POST /api/orders/{id}/inspect`, `/complete`, `/return`.
- `POST /api/orders/{id}/photo-card` и `POST /api/orders/{id}/photo`.
- `GET /api/orders/{id}/photo`.
- `POST /api/admin/settings`.
- `DELETE /api/orders/{id}` и `DELETE /api/logs/{id}` только для администратора.
- `POST /api/login` и `GET /api/health`.

Ошибка приходит как `{ "detail": "текст" }`. Страница показывает этот текст и не двигает заказ вперёд. Пока сервер выключен, остаётся прежнее демо в браузере.

## Что затронуто на странице

Чтобы экран говорил с сервером, изменены несколько файлов фронта. Внешний вид экранов тот же.

- `apiService.js` ходит на `http://127.0.0.1:8000` и при отказе показывает текст сервера.
- В списке ролей появилась служба безопасности. Ей виден только журнал.
- Сканирование больше не перерисовывает всю страницу, поэтому экран кадра не сбрасывается.
- Повторный кадр того же заказа заменяет файл и новую строку журнала не добавляет.
- Сохранение комиссии и тарифов уходит на сервер.
